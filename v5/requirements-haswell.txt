# v5 on a pre-2015 CPU. Use this instead of requirements.txt there.
#
#   uv pip install --python .venv-myo\Scripts\python.exe -r v5\requirements-haswell.txt
#   python scripts\prune_mujoco_plugins.py --apply
#
# Measured on an Intel Xeon E5-2650 v3 (Haswell, 2014), Windows 10 Enterprise
# 22H2 build 19045: torch 2.14.0's c10.dll and four of MuJoCo's six bundled
# plugins fail to load with
#
#     OSError: [WinError 1114] A dynamic link library (DLL) initialization
#     routine failed
#
# which Windows reports when a library loads and its own initialisation code
# then fails. Everything else on that machine checks out -- all eight MSVC
# runtime DLLs load, numpy and its native libraries load, mandatory ASLR is
# off, the OS is supported, the DLLs are not truncated, and the same failure
# happens from C: as from E:. The same wheels work on a 2025 CPU. So the
# wheels execute an instruction during library initialisation that Haswell
# does not have, and no amount of reinstalling changes that.
#
# Only two pins differ from requirements.txt.

# torch 2.5.1 loads on Haswell; 2.14.0 does not. Verified to be more than just
# importable: all 118 tests pass on it, and `--seed 7` produces iteration logs
# bit-identical to 2.14.0, so a run started here and continued there is the
# same run.
torch==2.5.1

# mujoco is NOT downgraded. 3.2.7's plugins fail on that CPU too, so the
# version is not the problem -- the plugins are, and only two of the six are
# needed. scripts/prune_mujoco_plugins.py moves the other four aside; run it
# after installing. Downgrading would also risk the MjSpec API, which
# myo_curriculum/env.py uses to restructure the model and which moved between
# 3.2 and 3.6.
mujoco==3.6.0
