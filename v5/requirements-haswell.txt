# v5 on a pre-2015 CPU. Use this instead of requirements.txt there, then run
#
#   uv pip install --python .venv-myo\Scripts\python.exe -r v5\requirements-haswell.txt
#   python scripts\prune_mujoco_plugins.py --apply
#
# Measured on an Intel Xeon E5-2650 v3 (Haswell, 2014), Windows 10 Enterprise
# 22H2 build 19045: torch 2.14.0's c10.dll and MuJoCo 3.6's bundled plugins
# fail to load with
#
#     OSError: [WinError 1114] A dynamic link library (DLL) initialization
#     routine failed
#
# which Windows reports when a library loads and its own initialisation code
# then fails. Everything cheaper was ruled out on that machine first: all
# eight MSVC runtime DLLs load, numpy and its native libraries load, mandatory
# ASLR is off, the OS is supported, c10.dll is not truncated, and the identical
# DLL fails from C: as well as from E:. The same wheels work on a 2025 CPU. So
# these wheels execute an instruction during library initialisation that
# Haswell does not have, and reinstalling cannot change it.
#
# Three pins differ from requirements.txt. All three combinations below were
# run here: 118 tests pass, and `--seed 7` gives iteration logs bit-identical
# to the current stack (ret -34.91, max -33.56, travel -0.272 m), so a run
# started on one machine and continued on the other is the same run.

# torch 2.5.1 loads on Haswell; 2.14.0 does not.
torch==2.5.1

# MuJoCo 3.6 bundles `obj_decoder` and `stl_decoder`, and *those* are among
# the plugins that will not initialise -- so pruning cannot help, because the
# MyoSuite meshes cannot be read without them. 3.3 decodes meshes in the core
# and bundles only `actuator`, `elasticity`, `sdf` and `sensor`, none of which
# this project uses, so all four can go.
#
# Downgrading mujoco means downgrading myosuite with it: myosuite 2.12.2
# requires mujoco>=3.6,<3.7. 2.11.6 pins 3.3 and ships the same
# simhive/myo_sim/body/myobody.xml -- verified identical in what matters, the
# compiled model being nq 49, nv 49, nu 290, the same root qpos addresses and
# the same 0.907292 m solved standing pelvis height as on 3.6.
mujoco==3.3.0
myosuite==2.11.6

# --- unchanged from requirements.txt ---------------------------------------
imageio==2.38.0
imageio-ffmpeg==0.6.0
pillow==12.3.0
pytest==9.1.1
matplotlib==3.11.2
numpy==2.5.3
# gymnasium 0.29.1, not the 1.2.3 of requirements.txt: myosuite 2.11.6 pins
# it exactly, so this is not a choice. The tests do not touch gymnasium's own
# API -- MyoLocomotionEnv only borrows its spaces -- and all 118 pass on it.
gymnasium==0.29.1
